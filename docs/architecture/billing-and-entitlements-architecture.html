1. Overview

Billing and entitlements are split into three layers: plan metadata (marketing copy and seed data), code entitlements (authoritative limits and feature flags), and runtime state on Organization (current planKey, Lemon Squeezy IDs, billing status).

  1. Entitlements — lib/entitlements.ts defines numeric limits and boolean features per plan.
  2. Usage — lib/usage.ts records PR checks in UTC calendar months with optional sourceKey dedupe.
  3. Billing — lib/billing.ts talks to Lemon Squeezy for checkout and customer portal; webhooks update org rows.
Code entitlements are authoritative Enforcement always calls getPlanEntitlements() from lib/entitlements.ts. The Plan table seeded from lib/plans.ts is for display and admin reference — not the runtime gate.

2. Plan Catalog (lib/plans.ts)

plans is a static array of five tiers with human-readable pricing, limit strings, and marketing feature bullets. isFeatureAvailable() delegates to getPlanEntitlements() for boolean feature checks.

Plan key Display price Primary positioning
free $0 Single repo, basic risk summary
starter $19/mo GitHub comments/check runs, higher usage
team $79/mo Approvals, custom rules, team governance
growth $199/mo Advanced scoring, audit export
enterprise Custom SSO/self-hosted placeholders, compliance

2.1 Database seed vs code

prisma/seed.ts creates Plan rows from the plans array (name, price, string limits, feature list). At runtime, however:

  • Organization.planKey is the active subscription tier.
  • Limits and features are read from planEntitlements in code, not from the Plan table.
  • Paid checkout maps variant IDs via env vars, not Plan table rows.
Keep seed and entitlements aligned If marketing limits in lib/plans.ts drift from lib/entitlements.ts, the UI may show incorrect plan copy while enforcement follows code. Update both when changing limits.

4. Usage Metering (lib/usage.ts)

4.1 Metric and periods

The sole metered metric is PR_CHECKS_METRIC = 'pr_checks'. Usage periods are calendar months in UTC: 

periodStart = UTC(year, month, 1)
periodEnd   = UTC(year, month + 1, 1)

getPrCheckUsage() aggregates UsageRecord.quantity for the current period. getPrCheckUsageHistory() returns up to six prior months (deduped by periodStart).

4.2 Recording with sourceKey idempotency

recordPrChecks(organizationId, quantity, now?, sourceKey?) creates a UsageRecord row. When sourceKey is provided, a unique constraint on [organizationId, metric, periodStart, sourceKey] prevents double-counting.

GitHub sync builds the key via getPrCheckSourceKey() in lib/github-sync.ts: 

{repositoryId}:{pullNumber}:{headSha}

The same key is checked in canRunPrCheck() before sync work begins — if a record already exists for that PR head in the current month, the check is allowed to proceed without consuming additional quota.

GitHub webhook / sync │ ├─ canRunPrCheck(orgId, sourceKey) │ ├─ existing UsageRecord for sourceKey? → allow (no new charge) │ └─ else canConsume(prCheckLimit, used)? → allow or block │ └─ after successful PR sync recordPrChecks(orgId, 1, now, sourceKey) increment repository.monthlyPrCheckUsage

5. Lemon Squeezy Integration (lib/billing.ts)

5.1 Billing mode

getBillingMode() returns one of three states:

Mode Condition Behavior
live LEMON_SQUEEZY_API_KEY and LEMON_SQUEEZY_STORE_ID set Real checkout and portal API calls
mock Not production, Lemon Squeezy not configured Dev-friendly; checkout may redirect with checkout_unavailable
unconfigured Production without Lemon Squeezy credentials Checkout API returns 503

5.2 Paid plans and variant mapping

isPaidPlan() is true for starter, team, and growth. Each maps to an env-backed variant ID:

Plan Env var
starter LEMON_SQUEEZY_STARTER_VARIANT_ID
team LEMON_SQUEEZY_TEAM_VARIANT_ID
growth LEMON_SQUEEZY_GROWTH_VARIANT_ID

5.3 Checkout

createCheckoutSession() POSTs to Lemon Squeezy /v1/checkouts with:

  • checkout_data.custom.organizationId and planKey for webhook correlation.
  • product_options.redirect_url from getBillingReturnUrl() (default /settings/billing).
  • Customer email/name from the authenticated owner session.

Handled by POST /api/billing/checkout.

5.4 Customer portal

getLemonSqueezyCustomerPortalUrl() fetches portal URL from subscription or customer API. Requires stored lemonSqueezySubscriptionId or lemonSqueezyCustomerId on the organization. Handled by POST /api/billing/portal.

5.5 Billing status labels

BillingStatus: trialing, active, past_due, paused, canceled. getBillingCallout() produces user-facing status strings for the billing page.

6. Subscription Webhooks (lib/lemon-squeezy-webhooks.ts)

Endpoint: POST /api/lemon-squeezy/webhook. Raw body is verified with HMAC-SHA256 against LEMON_SQUEEZY_WEBHOOK_SECRET (x-signature header).

6.1 Handled subscription events

Event Typical effect
subscription_created Set plan, billing status, Lemon IDs
subscription_updated Plan change, status sync; stale-active guard
subscription_cancelled canceled status, cancellation date
subscription_resumed Reactivate subscription
subscription_expired Downgrade to free
subscription_paused / subscription_unpaused Pause/resume billing state

Non-subscription events are recorded as ignored.

6.2 BillingWebhookEvent dedupe

Each delivery gets a deliveryId (SHA-256 of raw body). The BillingWebhookEvent table tracks:

Status Meaning
processing In-flight; retries within 5 minutes treated as duplicate
processed Successfully applied; subsequent deliveries skipped
ignored Unknown event, missing org, or stale update; final state

6.3 Organization lookup

getOrganizationLookup() resolves the org by, in order:

  1. meta.custom_data.organizationId from checkout
  2. lemonSqueezySubscriptionId from event data ID
  3. lemonSqueezyCustomerId from subscription attributes

6.4 Plan resolution

getPlanKeyFromLemonSqueezyEvent() prefers custom_data.planKey, then maps variant_id via env variant IDs. Expired subscriptions force planKey = 'free'.

Lemon Squeezy POST /api/lemon-squeezy/webhook │ ├─ verifyLemonSqueezyWebhookSignature(rawBody, x-signature) ├─ deliveryId = sha256(rawBody) ├─ BillingWebhookEvent upsert → processing ├─ lookup Organization ├─ update Organization (planKey, billingStatus, Lemon IDs, trial/cancel dates) ├─ AuditEvent (settings_changed, actor: Lemon Squeezy) └─ BillingWebhookEvent → processed

7. Runtime Enforcement

7.1 GitHub sync (lib/github-sync.ts)

Gate Function Limit
PR check quota canRunPrCheck() prCheckLimit per UTC month (with sourceKey dedupe)
Repository import syncGitHubInstallation() repositoryLimit — skips new repos when at cap
GitHub check runs shouldPublishGitHubCheckRun() features.githubComments (free plan blocked)

When canRunPrCheck returns false, PR sync is skipped entirely for that head SHA — no risk scoring, no usage record, no AI review enqueue.

7.2 UI enforcement

  • app/repositories/page.tsx — warns when repositoryLimit reached.
  • app/settings/usage/page.tsx — shows usage vs prCheckLimit.
  • app/settings/billing/page.tsx — plan comparison from entitlements.

8. Billing Access Control

canManageBilling(role) in lib/collaboration.ts returns true only for owner. Admins, members, and viewers cannot start checkout or open the customer portal.

Route / surface Check On denial
POST /api/billing/checkout canManageBilling(organization.role) 403 JSON
POST /api/billing/portal canManageBilling(organization.role) 403 JSON
app/settings/billing/page.tsx canManageBilling gates upgrade/portal buttons Read-only view for non-owners
Usage and billing pages are readable by all roles Only mutation paths (checkout, portal) require owner. Team members can see current plan and usage metrics.

10. Technical Caveats

Topic Detail
Plan table vs code Seeded Plan rows are not queried for enforcement. Always update lib/entitlements.ts.
Enterprise is manual No Lemon Squeezy variant; unlimited limits in code. Sales/onboarding must set planKey directly.
UTC month boundaries Usage resets on UTC month rollover, not org timezone.
Resync idempotency Same PR head SHA in a month does not double-charge thanks to sourceKey.
Stale subscription updates Active updates after cancel+free downgrade are ignored to prevent webhook race rewinds.
Mock mode in dev Checkout without Lemon Squeezy redirects with error param — not a simulated payment.
Owner-only billing Admins cannot upgrade; product decision to keep payment authority with workspace owner.

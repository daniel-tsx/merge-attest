1. Overview

MergeAttest's UI is a React Server Components (RSC)–first Next.js 16 app. Pages are async server components by default; client components are used for interactivity (shell navigation, filters, theme, forms). Data flows from lib/data/app-data.ts through cached server loaders — not client-side fetch libraries.

Server components by default List pages, detail pages, and dashboards fetch org-scoped data on the server. Client islands handle URL sync, sheets, command palette, and auth forms.

3. Request & Layout Path

HTTP request │ ▼ proxy.ts ← auth cookie gate, rate limits, CSRF, security headers │ sets x-mergeattest-pathname header ▼ app/layout.tsx ← fonts, ThemeProvider, NuqsAdapter, RootShell │ ├─ Public route? → skip org fetch, minimal shell └─ Authenticated → getCurrentOrganization() + getPlatformAdminContext() │ ▼ RootShell (client) ← publicRoutes check via usePathname() │ ├─ Public → bare min-h-screen wrapper └─ App → AppShell (sidebar, nav, command palette) │ ▼ app/**/page.tsx ← RSC page content

3.1 proxy.ts

Next.js 16 edge proxy (middleware equivalent). Injects x-mergeattest-pathname so the root layout can detect public routes without re-parsing. See authentication architecture for security details.

3.2 app/layout.tsx

Root server layout loads Geist fonts, wraps children in ThemeProvider → TooltipProvider → NuqsAdapter → RootShell. For authenticated routes it parallel-fetches organization context and admin flag to pass into the shell.

3.3 RootShell → AppShell

RootShell is a client component that branches on pathname:

  • Public — /, /sign-in, /sign-up, /forgot-password, /reset-password render children without sidebar.
  • Authenticated — AppShell provides sidebar navigation, org name, plan badge, data mode indicator, admin link, theme toggle, sign out.

AppShell defines nav sections (Overview, Governance, Settings) with Lucide icons and responsive sheet menu for mobile.

5. Data Layer (lib/data/app-data.ts)

Central server-side data access for the UI. All list/detail loaders scope queries by organizationId from session context.

5.1 getCurrentOrganization

Wrapped in React cache() — one lookup per request. Resolution order:

  1. ensureCurrentUserOrganization() — live session + membership → dataMode: 'live'.
  2. Production or DB configured without session → throws (auth required).
  3. Dev without DB → queryWithDemoFallback → demo org with dataMode: 'demo'.

Returns OrganizationContext: id, name, slug, planKey, billing fields, GitHub installation ID, role, and dataMode.

5.2 queryWithDemoFallback

async function queryWithDemoFallback(query, fallback, label)
  • No Prisma client → dev returns fallback(); production throws.
  • Query throws → production rethrows; dev logs warning and returns fallback().
  • Used by listRepositories, listPullRequests, and other loaders.

6. URL State — nuqs Pattern

Filterable list pages colocate parsers in search-params.ts and UI in filters.tsx. This keeps server and client in sync with shareable URLs.

6.1 search-params.ts (server)

Example: app/pull-requests/search-params.ts

  • Define parsers with parseAsString, parseAsStringLiteral, defaults.
  • createSearchParamsCache(parsers) — parse in RSC via cache.parse(searchParams).
  • createSerializer(parsers) — build links preserving filter state.

6.2 filters.tsx (client)

Thin wrapper around UrlFilterForm from components/app/url-filter-form.tsx, passing the same parser object and field definitions (search, select options).

7. Component Layers

7.1 components/ui — primitives

shadcn/ui building blocks: Button, Card, Table, Sheet, Badge, Input, Select, etc. Unstyled logic + Tailwind; no business semantics. Reused across app and admin.

7.2 components/app — product layer

Domain-aware, MergeAttest-specific components:

Component Role

page-header.tsx Standard page title block (eyebrow, title, description)
page-loading.tsx Skeleton fallbacks (DashboardSkeleton, TableSkeleton)

7.3 components/charts

Chart wrappers (e.g. dashboard-charts.tsx) for trend visualization on dashboard.

7.4 Rule of thumb

  • Need a generic button or dialog? → components/ui
  • Need PR risk badge or org shell? → components/app
  • Page-specific layout only used once? → colocate in app/.../page.tsx or a nearby module

8. Standard Page Composition

Most authenticated pages follow this structure:

export default function SomePage({ searchParams }) {
  return (
    <div className="space-y-6">
      <PageHeader eyebrow="…" title="…" description="…" />
      <Card>
        <CardContent>
          <SomeFilters />          {/* client, optional */}
          <Suspense fallback={<TableSkeleton />}>
            <SomeContent searchParams={searchParams} />
          </Suspense>
        </CardContent>
      </Card>
    </div>
  )
}

8.1 PageHeader

Consistent top-of-page hierarchy: optional eyebrow (section label), H1 title, muted description. Keeps vertical rhythm with space-y-6 or space-y-8.

8.2 Card + Suspense

  • Static shell (header, filters) renders immediately.
  • Async server child fetches data inside Suspense.
  • Skeleton from page-loading.tsx matches table/card layout.

9. Technical Caveats

Topic Detail
Dual public-route lists Public paths defined in both proxy.ts and RootShell — keep in sync when adding auth pages.
Layout org fetch skipped on public Root layout passes placeholder org name on public routes; no wasted DB call.
Demo data mode dataMode: 'demo' surfaces in shell badge; data may not reflect real GitHub state.
No global client store Org context comes from server per request, not Zustand/Redux.
Admin in same shell /admin uses AppShell with extra nav when isAdmin; layout guard is in app/admin/layout.tsx.
searchParams is a Promise Next.js 16 passes searchParams as async; await in RSC children.

1. Overview

Auteur security is layered: edge middleware (proxy.ts) applies rate limits, CSRF-style origin checks, and response headers; application code enforces session auth, RBAC, and plan entitlements; external callers use HMAC webhooks or Bearer job tokens. Sensitive values are never stored in plaintext where hashing or encryption is available.

Request │ ▼ proxy.ts rate limits · origin check · security headers · page cookie gate │ ├─ Browser API (session) → ensureCurrentUserOrganization + canManage* + organizationId scope ├─ GitHub / Lemon WH → HMAC verification before enqueue/process ├─ Job cron → Authorization: Bearer JOB_RUNNER_SECRET └─ Platform admin → session + ADMIN_EMAILS → 404 if not allowlisted
Fail closed in production validateProductionEnv() throws when core secrets and integration vars are missing. Webhook verification rejects unsigned requests. Job endpoints return 503 without JOB_RUNNER_SECRET.

2. Threat Model (Practical Scope)

Threat Mitigation Residual risk
Cross-tenant data access All app reads/writes scoped by organizationId from session context New endpoints must remember to scope; no DB RLS
CSRF on mutating APIs Same-origin check on POST/PUT/PATCH/DELETE (lib/security.ts) Exempt paths (auth, jobs, webhooks) rely on other auth
Webhook spoofing HMAC-SHA256 with timing-safe compare Dev/demo modes may accept unsigned GitHub webhooks
Secret leakage at rest AI keys encrypted; invite tokens hashed; passwords via Better Auth ApiKey.hashedKey schema exists; no request auth yet

Abuse / DoS In-memory rate limits at edge Per-instance buckets on serverless; not global

3. Tenant Isolation

Auteur is multi-tenant at the organization level. After session resolution, ensureCurrentUserOrganization() binds the request to one organization and role. Normal product data — repositories, pull requests, rules, audit events, billing state — is always queried with that organizationId.

3.1 Enforcement patterns

  • Never trust IDs alone — handlers load by primary key and verify organizationId matches session context.
  • Server actions — getCurrentOrganization() then role checks via lib/collaboration.ts.
  • API routes — ensureCurrentUserOrganization(); 401 if null.
  • Plan entitlements — separate from RBAC; enforced in lib/entitlements.ts and lib/plans.ts.

3.2 Cross-tenant exceptions (intentional)

Surface Scope Guard
Platform admin console All organizations ADMIN_EMAILS allowlist + requirePlatformAdmin()
GitHub webhooks Resolved after delivery processing Installation → organization mapping in webhook pipeline
Job runner endpoints Global queue processing JOB_RUNNER_SECRET Bearer token
Single-org session Session context uses the user's earliest membership. Accepting an invite to another org does not switch active tenant until multi-org switching is implemented.

4. Edge Security (proxy.ts)

Next.js edge middleware runs on almost all routes (excluding static assets). It runs before route handlers and complements — but does not replace — server-side auth.

4.1 CSRF / origin validation

Mutating API requests (POST, PUT, PATCH, DELETE) under /api/* must pass isTrustedMutationOrigin() in lib/security.ts: the Origin header (preferred) or Referer must match the request URL origin.

Exemption Reason
/api/auth/* Better Auth handles its own CSRF/trusted origins
/api/jobs/* External cron uses Bearer token, not browser cookies
Paths containing /webhook GitHub and Lemon Squeezy cannot send browser Origin

Failed origin checks return 403 with { error: 'Invalid request origin.' }.

4.2 Rate limiting

In-memory sliding window per IP + method + pathname (lib/rate-limit.ts):

Rule Limit Applies to
auth 30 / minute /api/auth/*
webhook 300 / minute Paths containing /webhook
mutation 90 / minute Non-GET API routes
public 120 / minute Everything else

Responses include X-RateLimit-* headers. Exceeded limits return 429.

Rate limits are process-local Buckets live in a module-level Map. On Vercel serverless / multi-instance deployments, each instance maintains separate counters. Use shared storage (Redis, edge KV) for global limits at scale.

4.3 Page auth gate (coarse)

App pages require a session cookie unless public or dev demo mode (no DATABASE_URL). API routes pass through; handlers validate auth themselves. See authentication architecture §7.

5. Webhook HMAC Verification

External webhooks are authenticated by shared-secret HMAC before any business logic runs.

Provider Header Algorithm Module
GitHub x-hub-signature-256 HMAC-SHA256 over raw body; prefix sha256= lib/github.ts → verifyGitHubWebhook()
Lemon Squeezy x-signature HMAC-SHA256 hex digest; timing-safe compare lib/lemon-squeezy-webhooks.ts → verifyLemonSqueezyWebhookSignature()

5.1 GitHub behavior

  • Production without GITHUB_WEBHOOK_SECRET → verification fails (missing_secret), 401.
  • Non-production without secret → mode: 'demo', verification succeeds for local testing.
  • Invalid or missing signature → 401; logged at warn via logEvent (webhook_verification_failed).
  • Uses timingSafeEqual to reduce timing oracle risk.

5.2 Lemon Squeezy behavior

  • unmarshalLemonSqueezyWebhook() verifies signature before JSON parse.
  • Invalid signature throws → route returns 401; reportError with lemon_squeezy_webhook_failed.
  • Delivery id derived from SHA-256 hash of raw body for idempotency.

6. Secrets at Rest

Secret type Storage Implementation
User passwords Account.password (hashed) Better Auth email/password provider
Session tokens Session.token Better Auth session management; cookie-bound
Team invite tokens OrganizationInvite.token = SHA-256 hex of raw token hashInviteToken() in lib/collaboration.ts; raw token only in URL/email
AI provider keys (OpenRouter) AiProviderCredential.encryptedKey AES-256-GCM (v1:iv:authTag:ciphertext) in lib/ai/credentials.ts
API keys (future) ApiKey.prefix + hashedKey Schema present; no middleware validates API keys on requests yet

6.1 AI key encryption

  • Encryption key derived: SHA-256(AI_PROVIDER_ENCRYPTION_KEY || BETTER_AUTH_SECRET).
  • Prefer dedicated AI_PROVIDER_ENCRYPTION_KEY in production; falls back to auth secret in dev.
  • redactSecret() masks keys in UI/logs (prefix + suffix only).
  • Rotation requires re-encrypting stored credentials — plan before changing the encryption key.

6.2 Invite token hashing

createInviteToken() generates a UUID without dashes. Only hashInviteToken(token) is persisted. Accept route hashes the query param before lookup — a DB leak does not expose usable invite links.

7. Platform Admin — 404 Pattern

The operator console at /admin/* uses least-disclosure authorization: unauthorized users see 404 Not Found, not 403 Forbidden.

  • requirePlatformAdmin() in lib/admin/access.ts calls notFound() when session email is not in ADMIN_EMAILS.
  • app/admin/layout.tsx invokes this guard for all admin pages.
  • Admin server actions re-check context?.isAdmin before mutations.
  • Cross-tenant reads intentionally go through lib/admin/admin-data.ts.
Rationale Hiding admin routes reduces scanner noise and avoids confirming that an admin surface exists to unauthenticated or non-admin users.

8. Security Headers (lib/security.ts)

applySecurityHeaders() runs on every response from proxy.ts:

Header Value
X-Content-Type-Options nosniff
X-Frame-Options DENY
Referrer-Policy strict-origin-when-cross-origin
Permissions-Policy camera, microphone, geolocation disabled
Cross-Origin-Opener-Policy same-origin
Cross-Origin-Resource-Policy same-origin
Strict-Transport-Security Production only: max-age=31536000; includeSubDomains; preload

Open redirect protection lives separately in lib/redirects.ts (safeRelativeRedirect) for post-login and invite callbacks.

9. Production Environment Validation

validateProductionEnv() in lib/env.ts is invoked from getPrismaClient() on every database access attempt. In production (NODE_ENV=production), missing required vars throw immediately: 

DATABASE_URL, BETTER_AUTH_SECRET, BETTER_AUTH_URL, BETTER_AUTH_API_KEY,
GITHUB_APP_ID, GITHUB_APP_SLUG, GITHUB_APP_PRIVATE_KEY, GITHUB_WEBHOOK_SECRET

This fail-closed pattern prevents partially configured deployments from serving live traffic with silent degradation. Development allows a hardcoded local auth secret fallback and demo mode without DATABASE_URL.

Variable Security role
JOB_RUNNER_SECRET Bearer auth for cron job endpoints (503 if missing in prod)
GITHUB_WEBHOOK_SECRET Webhook HMAC (required in prod validation list)
AI_PROVIDER_ENCRYPTION_KEY Recommended separate key for AI credential encryption
ADMIN_EMAILS Platform admin allowlist (optional but required for admin console access)
LEMON_SQUEZY_WEBHOOK_SECRET Billing webhook HMAC (checked at billing boundary, not in core prod list)

10. Known Limitations

Topic Detail
In-memory rate limits Not shared across serverless instances; effective limit scales with instance count.
Edge cookie gate Cookie presence ≠ valid session; handlers must call getServerSession().
RBAC not centralized Each route/action checks permissions individually — review new endpoints carefully.
No API key auth middleware ApiKey model exists; session-only user auth today.
No database RLS Tenant isolation enforced in application code, not PostgreSQL policies.
Dev demo bypass Without DB in dev, pages load without login — not representative of production.
GitHub webhook demo mode Unsigned webhooks accepted in non-production when secret unset.

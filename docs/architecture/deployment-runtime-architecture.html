1. Overview

AgentGate is a Next.js 16 App Router application deployed as serverless functions on Vercel (or compatible hosts). There is no long-running Node process — background work is triggered by external HTTPS cron hitting authenticated job routes. PostgreSQL is accessed via Prisma 7 with the @prisma/adapter-pg driver adapter.

Deploy (Vercel) │ ├─ pnpm install ├─ prisma generate (prebuild hook) ├─ next build └─ prisma migrate deploy (release phase / manual — see §4) Runtime request │ ├─ proxy.ts (edge) rate limit · CSRF · headers · page gate ├─ Route handler / RSC getPrismaClient() → validateProductionEnv() └─ External cron POST /api/jobs/* + Bearer JOB_RUNNER_SECRET

2. Vercel-Friendly Serverless Next.js

Aspect Behavior
Compute model Per-route serverless functions; cold starts possible
Edge middleware proxy.ts runs at the edge before app routes
Stateful globals Prisma client cached on globalThis; rate-limit buckets in-memory (per instance)
Background work Not in-process — external scheduler + /api/jobs/*
Deploy metadata VERCEL_GIT_COMMIT_SHA injected for log release field
after() GitHub webhook route uses Next.js after() for post-response queue drain (single delivery)
No built-in Vercel Cron in repo Job scheduling is documented as external HTTPS POST with Bearer token. Configure Vercel Cron, GitHub Actions, or another scheduler per docs/operations/OPERATIONS_RUNBOOK.md.

3. Build Pipeline

From package.json scripts:

Script When Purpose
pnpm db:generate Local dev / CI prisma generate — emits client to lib/generated/prisma/
prebuild Before next build Runs prisma generate automatically
pnpm build Deploy next build — production bundle
pnpm start Self-hosted next start after build
pnpm db:migrate Local dev only prisma migrate dev — creates/applies migration files

CI (`.github/workflows/ci.yml`) runs lint, typecheck, test, audit, and build with placeholder env values.

4. Database Migrations (Production)

Production schema changes use Prisma Migrate — not db push. Apply pending migrations at deploy time: 

pnpm db:generate
npx prisma migrate deploy

Run migrate deploy against the production DATABASE_URL before or immediately after deploying app code that depends on new schema. The operations runbook notes: if a migration was previously marked failed, inspect partial DB state before resolving — do not mark applied until tables/indexes/FKs exist.

  • Local development: pnpm db:migrate (prisma migrate dev)
  • Seed (optional): pnpm db:seed
  • Client import path: @/lib/generated/prisma/client

5. Environment Validation (lib/env.ts)

Central env accessors trim whitespace and return undefined for empty strings. validateProductionEnv() runs inside getPrismaClient() — any code path that opens the database validates production config first.

6. Demo Mode (Dev Without DATABASE_URL)

When PostgreSQL is not configured, the app still runs for UI exploration using in-memory demo fixtures from lib/demo-data.ts.

Component Demo behavior
getPrismaClient() Returns null when no DATABASE_URL
lib/auth.ts Omits Prisma adapter — auth cannot persist users/sessions
proxy.ts Non-production + no DB → app pages load without session cookie
lib/data/app-data.ts Falls back to demo data arrays when prisma is null
GitHub webhooks mode: 'demo' — received but not persisted/queued
getCurrentOrganization() Reports dataMode: 'demo' vs 'live'
Not production behavior Demo bypass and unsigned webhook acceptance exist only in development. Production requires full env validation and real persistence.

7. PostgreSQL Connection Pooling

Prisma connects via the official PostgreSQL driver adapter:

import { PrismaPg } from '@prisma/adapter-pg'
const adapter = new PrismaPg({ connectionString: databaseUrl })
new PrismaClient({ adapter })

The client is singleton-cached on globalThis (keyed by connection string) to survive serverless warm invocations and avoid connection storms on every request.

Pooling note for production Serverless functions open many short-lived connections. Point DATABASE_URL at a pooled endpoint (Neon pooler, Supabase pooler, PgBouncer, PlanetScale Postgres proxy, etc.) rather than a direct single-session URL when traffic scales. The adapter uses the pg driver; pool sizing is governed by the provider's pooler, not AgentGate application code.

8. External Cron — JOB_RUNNER_SECRET

Background processing is not embedded in the Next.js process. An external scheduler POSTs to job routes with: 

Authorization: Bearer <JOB_RUNNER_SECRET>

authorizeJobRequest() in lib/job-auth.ts:

  • Production without secret → 503 "Job runner secret is not configured."
  • Wrong/missing Bearer → 401
  • Development without secret → allowed (local testing)
Endpoint Purpose Recommended cadence
POST /api/jobs/github-webhooks Process queued/retryable GitHub webhook deliveries Every 1–5 minutes
POST /api/jobs/pr-reviews AI PR review worker queue Every 1–5 minutes
POST /api/jobs/retention Operational data cleanup (lib/retention.ts) Daily

Job routes are exempt from browser origin checks in proxy.ts because callers are server-side schedulers, not browsers. See docs/operations/OPERATIONS_RUNBOOK.md for expected JSON responses and alerting.

9. Edge Middleware — proxy.ts

Exported as Next.js middleware (export function proxy) with matcher excluding static assets. Runs at the edge on Vercel before route handlers.

Responsibility Detail
CSRF / origin Mutating /api/* same-origin check (exemptions for auth, jobs, webhooks)
Rate limiting Per-IP buckets; 429 when exceeded
Security headers applySecurityHeaders() on every response
Page auth gate Session cookie required for app pages (with public + demo exceptions)
Pathname header Sets x-agentgate-pathname for downstream use

Full security detail: security architecture. Auth detail: authentication architecture.

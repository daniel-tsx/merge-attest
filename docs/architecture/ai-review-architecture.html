AgentGate — AI Review Architecture

Advisory AI review pipeline: per-repository settings (disabled by default), encrypted OpenRouter credentials, idempotent job enqueue on PR sync, diff guardrails, and a worker that validates prerequisites but does not yet call the model. Verified against code as of June 2026.

1. Overview

AI review is an optional, per-repository feature layered on top of GitHub PR sync. It prepares diffs and tracks job state but intentionally stops before model inference — the worker ends in skipped with "AI model execution is not enabled yet."

  1. Settings — RepositoryReviewSettings; aiReviewsEnabled defaults to false.
  2. Enqueue — After PR sync, enqueueAiReviewJob() creates a job keyed by org/repo/PR/head SHA.
  3. Worker — Cron hits POST /api/jobs/pr-reviews; processQueuedAiReviewJobs() runs guardrails.
  4. Credentials — Organization-level OpenRouter key stored AES-256-GCM encrypted.
Disabled by default per repository New repositories inherit aiReviewsEnabled: false from getDefaultRepositoryReviewSettings(). Owners/admins must explicitly enable AI reviews and configure OpenRouter credentials at the org level.

Settings live in RepositoryReviewSettings (one row per repository). The module handles form parsing, defaults, normalization, and the enqueue gate.

2.1 shouldEnqueueAiReview

shouldEnqueueAiReview(settings) returns Boolean(settings?.aiReviewsEnabled). Called from:

  • enqueueAiReviewJob() — skips job creation when disabled.
  • processQueuedAiReviewJobs() — re-checks at worker time (settings may change after enqueue).

2.2 Form and UI

parseRepositoryReviewSettingsForm() reads server action FormData. Settings UI: app/repositories/[id]/ai/page.tsx. Org-level OpenRouter key: app/settings/ai/page.tsx.

3. Provider Credentials (lib/ai/credentials.ts)

Organization OpenRouter API keys are stored in AiProviderCredential (provider: 'openrouter'), encrypted at rest.

3.1 AES-256-GCM encryption

  • Algorithm: aes-256-gcm with 12-byte random IV.
  • Key derivation: SHA-256 of AI_PROVIDER_ENCRYPTION_KEY, falling back to BETTER_AUTH_SECRET.
  • Wire format: v1:{iv}:{authTag}:{ciphertext} (base64url segments).
  • encryptProviderKey() / decryptProviderKey() — round-trip for storage.
  • redactSecret() — UI display (sk-abc1...xyz9 pattern).

3.2 Lookup

getOrganizationOpenRouterCredential(organizationId) fetches the credential row. Worker blocks with status blocked when missing: "OpenRouter credentials are not configured yet."

Separate encryption key recommended Set AI_PROVIDER_ENCRYPTION_KEY in production so provider keys are not encrypted with the same material as session signing.

4. Job Lifecycle (lib/jobs/pr-review-lifecycle.ts)

4.1 reviewKey idempotency

getAiReviewKey() builds a unique string: 

{organizationId}:{repositoryId}:{pullNumber}:{headSha}

Stored as AiReviewJob.reviewKey (unique). Re-syncing the same PR head does not create duplicate jobs — enqueueAiReviewJob() returns the existing row.

4.2 Enqueue

enqueueAiReviewJob() preconditions:

  1. Prisma client available and headSha present.
  2. shouldEnqueueAiReview true for repository settings.
  3. No existing job for reviewKey (or catch unique violation and return existing).

Creates job with status: 'queued', optional githubDeliveryId, and queueJobId from getQueueJobId(PR_REVIEW_JOB_NAME, reviewKey).

Called from lib/github-sync.ts after successful PR record save.

4.3 Status transitions

getAiReviewTransitionData() sets timestamps: startedAt on in_progress; completedAt on terminal states. isTerminalAiReviewStatus() covers blocked, skipped, completed, failed.

5. Review Worker (lib/jobs/pr-review-worker.ts)

processQueuedAiReviewJobs({ limit?, now? }) processes up to limit (default 10) oldest queued jobs. Invoked by POST /api/jobs/pr-reviews (Bearer JOB_RUNNER_SECRET).

5.1 Processing steps

StepCheckOutcome if failed
1 Transition to in_progress, increment attemptCount —
2 shouldEnqueueAiReview(reviewSettings) skipped — "AI reviews are disabled for this repository."
3 getOrganizationOpenRouterCredential() blocked — "OpenRouter credentials are not configured yet."
4 getGitHubPullRequestDiff() via installation skipped — "GitHub diff is unavailable…"
5 filterDiffFiles(parseUnifiedDiff(rawDiff), { ignoredPaths }) skipped — "No reviewable diff remained after filtering."
6 Model execution skipped — "Diff guardrails passed; AI model execution is not enabled yet."

5.2 Result summary

Returns counts: processed, blocked, failed, skipped.

Uncaught errors → failed with errorMessage; reported via reportError().

Model execution deliberately disabled The worker validates the full prerequisite chain including diff guardrails, then stops. Publishing inline comments, managed comments, and check runs are configured in settings but not implemented in the worker yet.

6. Diff Processing (lib/github/diff.ts)

parseUnifiedDiff(rawDiff) parses GitHub unified diff into DiffFile[]. filterDiffFiles() applies review guardrails.

9. Technical Caveats

TopicDetail
Opt-in per repo Default aiReviewsEnabled: false. Enabling org credentials alone is insufficient.
No model calls yet Worker never decrypts the key or calls OpenRouter in current code.
Re-check at worker time Jobs queued before disable still run worker checks and may skip.
headSha required Enqueue skipped if PR head SHA missing.
One job per head New commits (new SHA) create new jobs; old jobs remain terminal.
Publish flags unused publishInlineComments, etc. stored but not acted on by worker.
Not plan-gated separately AI review availability follows repo settings + credentials, not a distinct plan flag.

1. Overview

MergeAttest maintains a tenant-scoped audit trail in PostgreSQL for governance and compliance workflows. Audit events capture human and system actions with actor, summary, and JSON metadata. A separate AgentActivity stream powers PR timeline UX for agent/CI activity — it is not the compliance audit log.

User / system action │ ├─ Governance-worthy? → AuditEvent (compliance, exportable) └─ PR timeline signal? → AgentActivity (UI feed, riskLevel, agentSource) Export flow (Growth+) GET /api/audit-log/export → listAuditEvents (plan retention window) → serializeAuditEventsToCsv (stream to client) → AuditExport row (metadata only — no CSV blob stored)

2. AuditEvent vs AgentActivity

Dimension AuditEvent AgentActivity
Purpose Compliance / governance evidence PR activity timeline in product UI
Timestamp field createdAt timestamp
Actor Optional (actor?); defaults to "system" in CSV Required string (user, agent, or "GitHub Checks")
Agent context Not stored agentSource + riskLevel
Event vocabulary AuditEventType — settings, sync, approvals, GitHub output ActivityEventType — CI, commits, merges, rule triggers
Retention Plan-based (auditRetentionDays); null = unlimited (Enterprise) Follows related PR/repo lifecycle; not export-gated
Export Included in CSV export API Not exported via audit export
Typical writers Server actions, settings, billing, sync, approvals GitHub webhook processor (CI status, GitHub reviews)
Dual-write example When a GitHub review webhook updates approval status, the processor creates both an AuditEvent (pr_approved / pr_rejected) and an AgentActivity (approved / rejected) in lib/github-webhooks.ts.

All rows include organizationId and optional repositoryId / pullRequestId FKs. Listing always filters by organization from session context.

4. Approval Audit Mapping (lib/approvals.ts)

When a user records an approval decision in app/pull-requests/actions.ts, helper functions map the domain decision to audit vocabulary:

Function Role
auditEventTypeForDecision(decision) Maps ApprovalDecision → AuditEvent.eventType
approvalStatusForDecision(decision) Maps decision → PullRequest.approvalStatus (not audit-specific)
approvalSummary(decision, prNumber) Human-readable AuditEvent.summary text
isApprovalDecision(value) Validates decision enum at action boundary

4.1 Decision → eventType

Decision audit eventType approvalStatus
approved pr_approved approved
rejected pr_rejected rejected
risk_accepted risk_accepted risk_accepted

Audit row metadata includes { decision, note, approvalStatus }. Structured ops logging uses logEvent with area: approval separately from the durable AuditEvent row.

5. Plan-Gated Retention

getAuditRetentionStart(planKey, now) in lib/audit-export.ts computes the earliest createdAt included in UI lists and exports: 

retentionDays = getPlanEntitlements(planKey).auditRetentionDays
if retentionDays === null → no cutoff (Enterprise unlimited)
else → now - retentionDays (UTC calendar days)
Plan auditRetentionDays auditExport feature
free 7 No
starter 30 No
team 180 No
growth 365 Yes
enterprise null (unlimited) Yes

app/audit-log/page.tsx and review packet API pass since: getAuditRetentionStart(planKey) to listAuditEvents().

6. CSV Export — GET /api/audit-log/export

6.1 Authorization layers

  1. Session + database — 401 if missing
  2. RBAC — canExportAudit(role) (owner/admin only) — 403
  3. Plan — isFeatureAvailable(planKey, 'auditExport') — 403 unless Growth or Enterprise

6.2 Query parameters

Filters mirror audit log search: query, eventType, actor, repositoryId, pullRequestNumber, severity, from, to. Hard cap: take: 10_000 events. Always applies plan retention since cutoff.

6.3 CSV serialization (lib/audit-export.ts)

serializeAuditEventsToCsv(events) produces RFC-style quoted CSV:

Column Source
created_at event.createdAt
event_type event.eventType
summary event.summary
actor event.actor ?? 'system'
repository event.repositoryName ?? ''
pull_request #${number} if present
metadata JSON.stringify(event.metadata)

csvCell() escapes quotes and prefixes cells starting with =, +, -, @, tab, or CR with ' to reduce CSV injection when opened in spreadsheets.

Response: Content-Type: text/csv, Content-Disposition: attachment; filename="mergeattest-audit-YYYY-MM-DD.csv". CSV bytes are streamed to the client — not persisted server-side.

7. AuditExport Metadata Table

After generating CSV, the route inserts an AuditExport row recording that an export happened — not the file contents.

Field Stored value
fileName e.g. mergeattest-audit-2026-06-03.csv
format csv (default)
filters JSON object of applied query filters (dates as ISO strings)
eventCount Number of rows in the export
createdById Exporting user's ID
organizationId Tenant scope
createdAt Export timestamp
No CSV blobs in the database The export artifact lives only in the downloader's browser/session. The AuditExport table provides an audit-of-audit trail (who exported what filters, how many events) without storing PII-heavy file payloads.

listAuditExports(organizationId) in lib/data/app-data.ts powers the export history panel on /audit-log.

8. Retention Cleanup Job (lib/retention.ts)

cleanupOperationalData() runs via POST /api/jobs/retention (Bearer-authenticated cron). Deletes:

Data Retention rule
AuditEvent Per-org: older than plan's auditRetentionDays (skipped if null)
GitHubWebhookDelivery Processed/ignored > 30 days
BillingWebhookEvent Processed/ignored > 365 days
AuditExport metadata rows > 30 days

Returns counts:

{
  "auditEventsDeleted": 0,
  "webhookDeliveriesDeleted": 0,
  "billingEventsDeleted": 0,
  "auditExportsDeleted": 0
}

Diagnostics (lib/diagnostics.ts) warns when stale processed webhook deliveries or audit export records exceed 30 days — indicating the retention job may not be running. Billing identifiers and usage records are not removed by this job.
